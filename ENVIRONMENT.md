# ENVIRONMENT.md — зафиксированное состояние среды сборки

Дата проверки: 26.10.2026. Команда для повторной проверки — см. ниже.

## Локальное окружение

- Компьютер: Windows 11, архитектура **x86-64 (AMD64)** — подходит по требованиям AOSP.
- Обязательно для полной сборки AOSP: ~400 ГБ диска и 64 ГБ ОЗУ (source.android.com/docs/setup/start/requirements).

## WSL2 / Ubuntu

- WSL2 работает, версия подсистемы — 2.
- Установлена **Ubuntu 24.04 LTS (noble)**, дистрибутив WSL: `Ubuntu-24.04`,
  находится в `D:\WSL\Ubuntu-24.04` (на диске D:, свободно ~164 ГБ).
- Проверено внутри Ubuntu (от root):
  - `uname -m` → **x86_64**
  - `lsb_release -a` → Ubuntu 24.04.5 LTS, codename **noble**
  - `free -h` → **9.7 GiB** ОЗУ выделено WSL по умолчанию (это 50% от ~20 ГБ системной RAM;
    этот лимит можно поднять через `.wslconfig`, но выше ~20 ГБ в сумме не будет)
  - `df -h ~` → виртуальный диск до 1 ТБ, реально ограничен свободным местом на D: (~164 ГБ)
  - `nproc` → **12** потоков CPU
  - swap WSL: 3 GiB

## Инцидент и восстановление (27.10.2026)

- Виртуальный диск Ubuntu (ext4.vhdx) был повреждён после ошибки монтирования
  `mount(/dev/sdd, /distro, ext4) failed 22` → `WSL_E_DISK_CORRUPTED`. Вероятная
  причина — некорректное завершение работы компьютера. Потеряно только
  окружение системы (без личных данных).
- По согласию пользователя выполнены `wsl --unregister` и повторная установка
  Ubuntu 24.04 в ту же папку `D:\WSL\Ubuntu-24.04`. Первая попытка упала с
  ошибкой сети `0x80072efe` (обрыв соединения при скачивании), вторая — успешна.
- Все проверки и установка базовых инструментов выполнены повторно, результаты
  идентичны прежним.
- Рекомендация: перед выключением/перезагрузкой Windows закрывать терминал
  Ubuntu и давать WSL завершить работу (`wsl --shutdown` при необходимости).

## Вывод по пригодности для полной сборки AOSP

Компьютер **НЕ соответствует официальным требованиям AOSP** для полной
сборки актуального Android (16–20 ГБ ОЗУ против 64 ГБ; ~164 ГБ свободно
против ~400 ГБ). Этого может быть достаточно для:
- изучения исходников, Git-репозитория и работы с манифестами,
- сборки отдельных модулей,
- разработки приложений-прототипов.
Для полноценной полной сборки нужен другой план: отдельная Linux-машина
или удалённая сборочная машина (с обсуждением стоимости до оплаты).

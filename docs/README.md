# Документация UnderVoltOS (UVOS)

Оглавление всех документов проекта. Все тексты — простым русским языком,
для начинающего разработчика; термины объясняются при первом использовании.

## Корневые документы

- [`README.md`](../README.md) — что такое UVOS, статус проекта.
- [`REQUIREMENTS.md`](../REQUIREMENTS.md) — требования и видение: концепция
  «закрытой территории», приоритеты, не-цели.
- [`DESIGN.md`](../DESIGN.md) — стильгайд: палитра, типографика, стили всех
  элементов управления (приборы, тумблеры, лампы, плитки), движение
  (без миганий — только статичные индикаторы), контрольный щиток (§6).
- [`ENVIRONMENT.md`](../ENVIRONMENT.md) — среда разработки (Windows 11 +
  WSL2/Ubuntu 24.04) и её ограничения.
- [`COMPATIBILITY_NOTES.md`](../COMPATIBILITY_NOTES.md) — исследование основ
  прошивки для sapphire/sapphiren (LineageOS-проект, ядро 5.15).

## Документация системы (папка docs/)

- [`ARCHITECTURE.md`](ARCHITECTURE.md) — архитектура: компоненты системы,
  ASCII-диаграмма, потоки данных, хранение правил, этапность.
- [`LIMITERS.md`](LIMITERS.md) — работа ограничителей: три слоя исполнения
  (приложения / фреймворк / ядро), 13 каналов данных, политика отказа,
  сетевой регулятор, журнал попыток, честные пределы.
- [`CONTROL-SCHEME.md`](CONTROL-SCHEME.md) — схема управления: роли
  (владелец/приложения/система), уровни экранов, потоки управления,
  профили ограничений, экстренные случаи.
- [`NETWORK-REGULATOR.md`](NETWORK-REGULATOR.md) — регулятор сети: три
  режима, белый список, лимиты и расписание, реализация (VPN → netfilter),
  честные пределы.
- [`SECURITY-AUDIT.md`](SECURITY-AUDIT.md) — аудит безопасности: соответствие
  стандартам ОС, анализ лазеек перехвата контроля и план устранения.
- [`PROTOTYPE.md`](PROTOTYPE.md) — прототип `uvos-dashboard`: что
  реализовано, как открыть в Android Studio, демо-режим, планы.
- [`TEST-CHECKLIST.md`](TEST-CHECKLIST.md) — план тестирования (этап E):
  происхождение образов, загрузка, связь, мультимедиа, обязательный
  блок NFC, датчики, специфика UVOS, шифрование и обновления.
- [`GLOSSARY.md`](GLOSSARY.md) — глоссарий: 61 термин проекта и Android
  простыми словами + как читать статусы в документах.
- [`ROADMAP.md`](ROADMAP.md) — дорожная карта этапов A–F со статусами
  и критериями завершения.

## Код прототипа

- [`uvos-dashboard/`](../uvos-dashboard/) — Kotlin-прототип приборной панели

## Правила ведения документации

1. Документ и код меняются одним коммитом, если связаны.
2. Непроверенное помечается «требует проверки» — не выдумываем факты.
3. Никаких личных данных, паролей, IMEI, инструкций по прошивке.
4. Тексты пишутся в настоящем проектном времени: «планируется/спроектировано»,
   а не «работает», пока это не подтверждено сборкой и тестом.

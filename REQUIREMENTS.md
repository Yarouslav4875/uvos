# REQUIREMENTS.md — UnderVoltOS (UVOS)

Статус: черновик видения и требований. Этап C (прототип) ещё не начат.
Важно: на этом этапе UVOS — это концепция и будущее имя проекта; НЕ «готовая ОС».
Первый практический шаг — приложение/лаунчер-прототип, затем (на другом
компьютере/сервере) — сборка на базе проверенной Android-основы.

## 1. Имя и идентичность

- Название: **UnderVoltOS**, сокращение **UVOS**.
- Основание для имени (задумка автора): подчёркивать «приборность» и контроль
  энергопотребления/нагрузки — тема вольтметров/амперметров.
  ⚠ Проверить позже, свободно ли имя как товарный знак/маркет, и не занято ли
  на F-Droid/GitHub.

## 2. Визуальный стиль

- Референс: скриншот домашнего экрана от автора (сохранён в проекте).
- Стиль: **ретро-приборы** (VU-метры, амперметры, вольтметры: бледный
  циферблат, чёрные шкалы, красная зона/стрелка, маленькие «лампочки»)
  в смеси с **минимализмом iPhone** (чистые тёмные плитки, аккуратная сетка,
  крупная типографика).
- Палитра: почти чёрный фон (#0E0E12-подобный), тёмно-графитовые плитки,
  бледный циферблат (#E8E4D8-подобный), акцентный красный (#E02020-подобный).
  Точные значения зафиксируем в прототипе.
- Элементы интерфейса: стрелочные индикаторы (заряд, температура, громкость,
  загрузка), моноширинная/индустриальная типографика, плиточная сетка.

### 2.1 Дизайн-система UVOS v1 (первая фиксация, 27.10.2026)

**Палитра:**
- `uvos_background` #0E0E12 — почти чёрный фон экрана;
- `uvos_tile` #1C1E26 — плитки/карточки;
- `uvos_dial` #E8E4D8 — бледный циферблат приборов;
- `uvos_dial_text` #1A1A1A — чернила на циферблате (деления, стрелка);
- `uvos_red` #E02020 — красная зона шкалы, акценты, красные «лампочки»;
- `uvos_text` #D8D8DC — обычный текст;
- `uvos_text_dim` #8A8A92 — приглушённый текст.

**Правила приборов (GaugeView):**
- Шкала: размах 270°, деления каждые 10%, жирные деления каждые 50%.
- Красная зона — последние 20% шкалы (как красные цифры на VU-метре).
- Подписи MIN/MAX в нижних углах циферблата, название прибора сверху.
- «Лампочка» подсветки в правом верхнем углу корпуса.
- Стрелка движется плавно (~0.6 с, замедление в конце — инерция настоящего
  прибора).

**Правила сетки:**
- Отступы 16dp от краёв экрана; плитки со скруглением 28dp.
- Приборы: полная ширина, высота ~220dp.

Текущая реализация: `uvos-dashboard/app/src/main/java/com/uvos/dashboard/GaugeView.kt`.

## 3. Главная концепция: «закрытая территория» для приложений

Суть: по умолчанию приложение не получает НИКАКИХ данных об устройстве и
пользователе, пока владелец явно не выдал разрешение. Интернет — тоже
разрешение, с регулировкой (какие приложения, когда, куда).

### 3.1 Что блокируется по умолчанию (список автора, расширенный)

- Время и дата (точное время; допускается огрубление до минут/часов/дня).
- Заряд батареи и её состояние.
- Список установленных приложений.
- IMEI/серийники, номера, идентификаторы рекламы.
- Геолокация, камера, микрофон, контакты, СМС, звонки, файлы.
- Сетевая активность других приложений.
- Датчики (шагомер, приближение и т.п.).

### 3.2 Интернет

- Разрешение на сеть выдаётся явно и управляется детально:
  приложение/домен/тип трафика/расписание.
- Идеал автора: приложение без разрешения не имеет сети вообще.

### 3.3 Честная оценка реализуемости (важно! не обещать лишнего)

Часть требований достижима СРЕДСТВАМИ Android (разрешения, Private Compute,
ограничения фоновой активности, VPN-фильтр для сети, работа без разрешений).
НО есть фундаментальные ограничения платформы:

- **Точное время**: стороннее приложение в Android может читать время всегда
  (это часть базового API). Полная изоляция времени возможна ТОЛЬКО правками
  самой ОС (framework/AOSP) — т.е. это цель уровня «прошивка», не приложения.
- **Заряд батареи**: API читается без разрешения (ACTION_BATTERY_CHANGED);
  изоляция требует правок системы или паддинга/подмены значений.
- Это НЕ значит «невозможно» — это значит, что полная «закрытая территория»
  требует собственной прошивки (наш долгосрочный план), а прототип покажет
  концепцию и всё, что достижимо на уровне приложения/лаунчера.

### 3.4 Приоритеты (предложение, подтвердит автор)

1. П-1: Видимость разрешений и их полный запрет по умолчанию.
2. П-1: Регулятор сети (белые списки, индикация трафика).
3. П-1: Приборная панель UVOS (стрелочные индикаторы) как лицо системы.
4. П-2: Огрубление времени/батарейных данных там, где платформа позволяет.
5. П-3: Полная изоляция времени/заряда (только уровень прошивки).

## 4. Целевое устройство разработки

- Этап C (прототип): любой Android-эмулятор/телефон без модификаций.
- Этап D/E (прошивка): Redmi Note 13 4G NFC (23124RA7EO, sapphire/sapphiren)
  — только после завершения исследований совместимости и на подходящей
  сборочной машине.

## 5. Не-цели текущего этапа

- Не прошивать телефон, не разблокировать загрузчик.
- Не обещать, что UVOS — полноценная ОС до подтверждённой сборки.
- Не собирать полный AOSP на текущем компьютере (ресурсы недостаточны,
  см. ENVIRONMENT.md).
